## 使用方法

### 1. 查找目标代码中的某个功能

**场景**：你想知道目标版本的"一键购买彩玉"是怎么实现的

1. 打开 `formatted_528/BatchDailyTasks-CDlX_GQ6.js`
2. 搜索中文字符串 `"一键购买彩玉"`
3. 找到对应函数，记录行号
4. 打开 `mappings/BatchDailyTasks_mapping.md`
5. 查找该行号附近的 minified 变量名映射
6. 将 minified 代码翻译为可读代码

### 2. 判断某个函数是否需要移植

**场景**：你想知道 `handleBuyColorJade` 是否需要移植

1. 打开 `annotations/BatchDailyTasks_annotations.md`
2. 在[新增]或[修改]列表中搜索该函数
3. 如果在[共享]列表中 → 跳过，无需移植
4. 如果在[新增]或[修改]列表中 → 需要移植

### 3. 移植一个函数的完整流程

```
Step 1: 在 annotations/ 中确认函数类型（新增/修改）
Step 2: 在 formatted_528/ 中找到该函数的完整代码
Step 3: 在 mappings/ 中查找变量名映射
Step 4: 对照映射表将 minified 代码翻译为可读代码
Step 5: 在开源源码中找到对应位置
Step 6: 用开源项目的代码风格重写该函数
Step 7: 验证功能正确性
```

### 4. 查看整体差异

- **总报告**：`analysis_report.md` — 包含完整的差异分析、Capacitor 替换方案、模块重组清单
- **总览**：`annotations/overview.md` — 包含增量统计和按优先级排序的移植任务清单

## 映射表格式说明

每条映射的格式为：

```
minified名 → 源码名 | 类型 | 位置 | 说明
```

示例：

```
r → ref | Vue API | 全局 | Vue 3 ref 函数
p → computed | Vue API | 全局 | Vue 3 computed 函数
Ae → handleBuyColorJade | 方法 | L1234 | 一键购买彩玉
```

注意：同一字母在不同作用域内可能代表不同变量（如 `s` 在顶层是 `useMessage`，在 `createCarManager` 内是 `tokenStore` 参数），映射表中已标注作用域。

## 增量标记格式说明

| 标记 | 含义 | 操作 |
|------|------|------|
| [新增] | 开源没有，目标新增 | 需要从零实现 |
| [修改] | 开源有，但目标改了 | 需要调整现有代码 |
| [共享] | 两边完全相同 | 跳过，无需处理 |
| [删除] | 开源有，目标删除了 | 需要移除 |

## Capacitor 代码替换速查

| 目标代码 | Web 替换方案 |
|---------|-------------|
| `isCapacitor()` | 删除或始终返回 false |
| `CrossPlatformStorage` | 直接用 localStorage |
| `getEnvironment()` | 始终返回 `'browser'` |
| `WakeLockManager` (Capacitor) | `navigator.wakeLock` |
| `window.Capacitor.Plugins.Filesystem` | `Blob + URL.createObjectURL + <a download>` |
| `window.Capacitor.Plugins.Share` | `navigator.share()` 或复制到剪贴板 |
| `window.Capacitor.getPlatform()` | 删除 |
