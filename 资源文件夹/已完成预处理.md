## 三、关键背景知识

### 3.1 目标代码的来源和形式

目标网站是开源项目经过 Vite 生产构建后的产物。代码仅做了 **minify**（变量名压缩为单字符），**没有混淆**，逻辑结构完整保留。prettier 格式化后可读性约 60-70%，对照开源源码映射变量名后可达 90%+。

### 3.2 目标使用 Capacitor 打包 APK

目标将 Web 应用通过 Capacitor 打包为 Android APK。Capacitor 提供的原生 API（文件系统、分享、防休眠等）在 Web 环境中不可用，必须替换为 Web API。

### 3.3 版本选择

APK 528 = 目标网站 ena.pages.dev = xiaohuaxyzw.top（字节级完全一致）。所有移植工作以 APK 528 的代码为准。

### 3.4 基线选择

使用**开源项目最新 main 分支**作为基线（而非目标旧版），因为开源最新版有更多 bug 修复和协议更新。

## 六、Capacitor → Web 替换速查表

| 目标代码 | Web 替换方案 |
|---------|-------------|
| `isCapacitor()` | 删除或始终返回 false |
| `CrossPlatformStorage` | 直接用 localStorage（后续可升级 IndexedDB） |
| `getEnvironment()` | 始终返回 `'web'` |
| `WakeLockManager` (Capacitor) | `navigator.wakeLock.request('screen')`，不支持时用 setInterval 心跳 |
| `Capacitor.Plugins.Filesystem` | `Blob + URL.createObjectURL + <a download>` |
| `Capacitor.Plugins.Share` | `navigator.share()`，不支持时降级为 Blob 下载 |
| `window.Capacitor.getPlatform()` | 删除 |
| `@capacitor-community/keep-awake` | `navigator.wakeLock` |
| `@tauri-apps/api/core` invoke | 删除，Web 不需要 |

## 七、移植工作流程（按组件同步推进）

```
对于每个组件/tab：

Step 1: 在 annotations/ 中确认函数类型
        [新增] → 从零实现
        [修改] → 调整现有代码
        [共享] → 跳过
        [删除] → 移除

Step 2: 在 formatted_528/ 中找到该组件的 render 函数
        → 提取 createVNode/createTextVNode 调用
        → 逆向还原为 <template>

Step 3: 在 formatted_528/ 中找到该组件的 setup 函数
        → 在 mappings/ 中查找变量名映射
        → 在 translations/ 中查找已翻译版本（如有）
        → 逆向还原为 <script setup>

Step 4: 对照模板和逻辑，确认数据流完整
        → 模板绑定的变量 = script 中必须定义的 ref/computed
        → 模板绑定的 @click = script 中必须定义的函数
        → 模板使用的组件 = script 中必须 import

Step 5: 用开源项目的代码风格写入
        - 使用 Vue 3 Composition API + <script setup>
        - 使用 Naive UI 组件
        - 替换所有 Capacitor API 为 Web API
        - 保持与开源项目一致的命名和代码风格

Step 6: 构建验证
        npm run lint && npm run build

Step 7: 视觉对比验证（见第九节）
```

## 八、必须修复的问题

### 8.1 🔴 重复组件清理

当前有 **21个组件存在两份**（小写目录 vs 大写目录），必须统一：

**处理方式**：
1. 确定统一的目录结构规范（建议用大写目录：Cards/、Club/、Rank/、Tower/、Team/、Common/、Daily/、Fight/）
2. 删除小写目录中的重复文件和根目录中的孤立文件
3. 统一所有 import 路径

### 8.2 🔴 eval 安全风险

BatchDailyTasks.vue 中有2处 `eval(taskName)`，必须替换为函数映射表：

```javascript
// ❌ 当前（危险）
const taskFunction = eval(taskName);

// ✅ 替换为
const TASK_FUNCTION_MAP = {
  batchClaimDailyRewards: () => batchClaimDailyRewards(),
  batchBuyColorfulJade: () => batchBuyColorfulJade(),
  // ...所有任务函数
};
const taskFunction = TASK_FUNCTION_MAP[taskName];
if (!taskFunction) {
  console.error(`未知任务: ${taskName}`);
  return;
}
taskFunction();
```

## 十一、已知风险和注意事项

### 11.1 代码风险

| 风险 | 等级 | 说明 |
|------|------|------|
| `eval(taskName)` | 🔴 高 | 必须替换为函数映射表 |
| localStorage 7天ITP限制 | 🟡 中 | Safari 会7天后静默清除 localStorage，Token可能丢失。后续可迁移到 IndexedDB |
| 大chunk警告 | 🟢 低 | GameFeatures.js 约1MB，目标本身2.5MB未做代码分割，暂不需要处理 |
| 翻译文档覆盖率低 | 🟡 中 | 仅6%，大量函数需直接读 minified 代码 |

### 11.2 移植难点

1. **UI/模板还原**：目标的 render 函数需要逆向为 Vue template，这是最耗时的步骤
2. **DailyTaskRunner 重构**：从单一 run() 拆分为11个 build* 方法，重构幅度大
3. **GameFeatures 子组件**：42个子组件需要逐个从 render 函数还原
4. **Capacitor 替换**：所有 Capacitor API 必须替换，不能遗漏

## 十三、与下一个人的沟通要点

1. **先读本文档**：这是完整的项目背景和执行方案
2. **再读 `备份/使用说明.md`**：这是预处理产物的使用手册
3. **然后读 `annotations/overview.md`**：这是按优先级排序的移植任务清单（52项，预估136h）
4. **翻译参考文档优先使用**：`translations/` 中的4个文件已经将 minified 代码翻译为可读代码，比直接读 formatted_528 高效得多
5. **⚠️ UI/模板必须与逻辑同步移植**：不要先写逻辑再补UI！每完成一个组件就同时完成模板和逻辑
6. **Capacitor 必须全部替换**：任何 `Capacitor`、`@tauri-apps`、`isCapacitor()` 引用都必须替换为 Web API
7. **eval 必须替换**：用函数映射表替代 `eval(taskName)`
8. **重复组件必须清理**：统一目录结构，删除重复文件
9. **每完成一个组件就验证**：`npm run lint && npm run build`
10. **视觉对比验证**：目标网站和用户网站都可以直接访问，逐页对比
11. **构建验证命令**：`cd opensource && npm install && npm run build`
